# 리텐션 캠페인 A/B 테스트 설계

실제 캠페인 결과가 아닌 REES46 공개 로그 기반 사전 설계안이다. 과거 관측 재방문율은 표본 설계용 참고값이며 실제 캠페인 성과나 인과효과가 아니다.

## 대상과 시간 경계

- 기준일: **2020-03-31, UTC 하루 전체**. 사전 입력은 `event_time < 2020-04-01 00:00:00 UTC`로 제한한다.
- 위험군: 기준일과 마지막 활동의 UTC 날짜 차이가 **15–29일(양끝 포함)**인 사용자.
- 층화 변수: 기준일 종료 이전 구매가 한 번이라도 관측됐는지(`is_buyer_at_reference`). 구매 여부만으로 고가치·저가치를 단정하지 않는다.
- 결과 관찰: **2020-04-01 00:00:00 이상, 2020-05-01 00:00:00 미만 UTC**, 30일간의 활동 여부.
- 전체 관찰 기간은 2019-10부터다. '구매 경험'은 이 데이터 내 관측 구매이며, 그 이전 이력은 알 수 없다.

7개월 전체 `user_features.parquet`의 `is_buyer`에는 4월 구매가 포함된다. 이 피처는 사후 기술통계에만 사용하며 A/B 대상 층화에 조인하지 않는다. `recency_days` 역시 4/30 기준이므로, 기존 `recency_at_reference.parquet`의 3/31 기준 날짜 차이를 사용한다.

## 배정과 분석 단위

- 하나의 캠페인으로 설계하고 각 구매 이력 층 안에서 사용자 단위로 처치·대조를 1:1 무작위 배정한다.
- 대상 풀에서 표본을 추출할 때는 층별 비중을 유지한다. 층마다 같은 수를 뽑으면 전체 모집단과 구성이 달라지므로, 그런 설계를 채택할 경우 가중치와 주 추정량부터 다시 정한다.
- Primary 분석은 최초 배정된 모든 사용자를 분모로 하는 ITT로 한다. 미열람·미클릭 사용자를 사후 제외하지 않는다.
- 전체 효과가 1차 판단이고 층별 효과는 탐색적 분석이다. 층별 확정 판단을 원하면 다중비교와 검정력을 반영해 별도로 설계한다.
- SRM(배정 비율 이상), 사용자 중복 배정·노출, 관찰 누락을 확인한 뒤 결과를 해석한다. 결과를 보며 임의로 조기 중단하지 않는다.

## 처치와 지표

- 처치군: 개인화 리마인드 1회. 대조군: 기존 안내 유지. 할인 정책은 두 군 동일.
- Primary: 배정 후 30일 내 한 번 이상 활동한 사용자 / 해당 군의 전체 배정 사용자.
- Secondary: 구매 사용자 / 전체 배정 사용자, 객단가. 원본 로그에는 주문 ID가 없어 객단가의 주문 단위 산식은 서비스 데이터 확보 후 확정한다.
- Guardrail: 수신거부율, 할인 비용, contribution margin. 분모·허용 악화폭은 실제 운영 정책과 원가 자료 확보 후 실행 전에 확정한다.

## 표본 설계와 판단 기준

유의수준 0.05, 검정력 0.80, 두 비율의 양측 검정, 처치·대조 1:1을 가정한다. `NormalIndPower`와 `proportion_effectsize`로 계산한 표본은 항상 올림한다.

**MDE +5%p는 표본 설계의 대립효과 크기**다. 관측 효과가 반드시 +5%p 이상이어야 한다는 자동 성공 규칙과 같지 않다. 실제 판단은 사전 지정한 전체 효과·신뢰구간, 비용을 고려한 실질 기준, guardrail을 함께 평가한다. 운영 비용과 허용 악화폭이 미확정이므로 이 문서만으로 바로 캠페인을 집행할 수는 없다.

## 정정과 검증 기록 · 2026-09-12

기존 계산은 recency만 기준일 이전으로 제한하고 구매 여부에는 4월까지 포함했다. 그 결과 위험군에서 **32,583명**이 기준일 당시 비구매자였는데 구매자로 분류됐다. 기존 구매군 47.60%·비구매군 21.79%와 그에 기반한 층별 표본 수는 위 재계산값으로 대체한다. 기존의 1,568명 표기는 당시 노트북 올림 결과 1,569명과도 달랐다.

기존 전체 위험군 2,200,340명과 재방문자 571,010명은 유지됐다. 미래 구매 이력을 제외하면 구매 이력 층의 구성과 baseline이 달라지는 문제였다. 31.5% vs 10.3% 역시 4월 포함 사후 구성비여서 사전 구매 경험의 예측력이나 인과효과로 해석하지 않는다.

- 원본 2019-10–2020-03의 3개 컬럼을 50만 행씩 읽어 구매 여부를 재계산했다. 원본은 수정·이동·복사하지 않았다.
- 기존 3/31 recency와 4월 결과 라벨을 재사용했다. 전체 재방문 간격·라벨·원본 코호트를 새로 계산한 것은 아니다.
- 구매군이 사전 활동자에 포함되는지, 위험군에 누락·판단 보류 라벨이 없는지, 층별 인원과 재방문자 합계가 전체와 맞는지 검사했다.
- 날짜 경계, 미래 구매 추가·변조 불변성, 청크·중복 불변성, 위험군 경계, 누락 라벨, 표본 계산을 회귀 검사한다.
- [`reports/ab_design_validation.json`](../reports/ab_design_validation.json)에 입력 범위와 정정 영향을 기록했다. 사용자별 정보는 공개하지 않는다.

## 재현

기존 `data/processed/recency_at_reference.parquet`, `churn_labels.parquet`, 정정 비교용 `user_features.parquet`가 필요하다. 이 사용자별 파일은 Git에 포함되지 않는다.

```bash
export ECOM_DATA_DIR="/path/to/monthly-csv-directory"
python -m src.ab_design
python -m unittest discover -s tests -v
```

실행 후 `05_ab_test_design.ipynb`에서 같은 집계와 저장된 CSV의 일치를 확인할 수 있다. 입력 기준일을 바꾸려면 recency와 결과 라벨도 함께 새로 만들어야 한다.
