# 리텐션 캠페인 A/B 테스트 설계

실제 캠페인 결과가 아닌 REES46 공개 로그 기반 사전 설계안이다. 과거 관측 재방문율은 표본 설계용 참고값이며 실제 캠페인 성과나 인과효과가 아니다.

## 대상과 시간 경계

- 기준일: **2020-03-26, UTC 하루 전체**. 사전 입력은 `event_time < 2020-03-27 00:00:00 UTC`로 제한한다.
- 위험군: 기준일과 마지막 활동의 UTC 날짜 차이가 **14–34일(양끝 포함)**인 사용자.
- 층화 변수: 기준일 종료 이전 구매가 한 번이라도 관측됐는지(`is_buyer_at_reference`). 구매 여부만으로 고가치·저가치를 단정하지 않는다.
- 결과 관찰: **2020-03-27 00:00:00 이상, 2020-05-01 00:00:00 미만 UTC**, 35일간의 활동 여부.
- 전체 관찰 기간은 2019-10부터다. '구매 경험'은 이 데이터 내 관측 구매이며, 그 이전 이력은 알 수 없다.

상한은 전체 7개월의 관측 재방문 간격 p90을 참고해 확정한 35일 기준 미만으로 둔다. 하한은 사후 정보를 사용하지 않도록 기준일 이전 분포의 p75 + 1일로 정한다. 전체 기간과 사전 기간의 분위수를 나란히 보고하며, p75·p90의 선택은 운영 기준이고 최적값으로 검증한 것은 아니다.

하한은 기준일 이전 완료 간격 p75(13일)에 1일을 더한 운영 기준. 사전 분포의 p75·p90은 13·31일, 전체 7개월은 14·35일이다. 관측 창이 짧은 사전 분포는 긴 간격을 덜 관측할 수 있다. Recency 구간은 0–7 / 8–13 / 14–34 / 35+다.

7개월 전체 `user_features.parquet`의 `is_buyer`는 관찰 기간 구매까지 포함하는 사후 기술통계다. A/B 층화에는 3/26 UTC 종료까지의 별도 사전 구매 캐시를 사용한다.

## 배정과 분석 단위

- 하나의 캠페인으로 설계하고 각 구매 이력 층 안에서 사용자 단위로 처치·대조를 1:1 무작위 배정한다.
- 대상 풀에서 표본을 추출할 때는 층별 비중을 유지한다. 층마다 같은 수를 뽑으면 전체 모집단과 구성이 달라지므로, 그런 설계를 채택할 경우 가중치와 주 추정량부터 다시 정한다.
- Primary 분석은 최초 배정된 모든 사용자를 분모로 하는 ITT로 한다. 미열람·미클릭 사용자를 사후 제외하지 않는다.
- 전체 효과가 1차 판단이고 층별 효과는 탐색적 분석이다. 층별 확정 판단을 원하면 다중비교와 검정력을 반영해 별도로 설계한다.
- SRM(배정 비율 이상), 사용자 중복 배정·노출, 관찰 누락을 확인한 뒤 결과를 해석한다. 결과를 보며 임의로 조기 중단하지 않는다.

## 처치와 지표

- 처치군: 개인화 리마인드 1회. 대조군: 기존 안내 유지. 할인 정책은 두 군 동일.
- Primary: 배정 후 35일 내 한 번 이상 활동한 사용자 / 해당 군의 전체 배정 사용자.
- Secondary: 구매 사용자 / 전체 배정 사용자, 객단가. 원본 로그에는 주문 ID가 없어 객단가의 주문 단위 산식은 서비스 데이터 확보 후 확정한다.
- Guardrail: 수신거부율, 할인 비용, contribution margin. 분모·허용 악화폭은 실제 운영 정책과 원가 자료 확보 후 실행 전에 확정한다.

## 표본 설계와 판단 기준

유의수준 0.05, 검정력 0.80, 두 비율의 양측 검정, 처치·대조 1:1을 가정한다. Cohen’s h를 효과크기로 사용한 statsmodels `NormalIndPower`로 계산하고, 군당 표본 수를 올림한다.

**MDE +5%p는 표본 설계의 대립효과 크기**다. 관측 효과가 반드시 +5%p 이상이어야 한다는 자동 성공 규칙과 같지 않다. 실제 판단은 사전 지정한 전체 효과·신뢰구간, 비용을 고려한 실질 기준, guardrail을 함께 평가한다. 운영 비용과 허용 악화폭이 미확정이므로 이 문서만으로 바로 캠페인을 집행할 수는 없다.

## 검증과 과거 기록

[자동 검증](../reports/recency_reference_validation.json)의 상태는 검증 당시 값이다. 이후 독립 대조와 조건 충족은 [별도 검토 기록](../reports/independent_review_record.json)에 남겼다. Claude는 3월 컷오프, 2월 3일치 원본 활동, 표본 1,000명과 사용자별 집계를 대조했다. 6개월 전체 원본과 사전 구매자 수는 별도 원본 재계산 범위에 포함되지 않았다. 현재 [구매 캐시 검증](../reports/ab_design_validation.json)은 생성 출처와 사전 구매자 수를 기록한다.

[일수별 재방문율](../reports/recency_day_outcome_comparison.csv)은 기술통계다. Recency 28일에 해당하는 2020-02-27에는 인접일보다 원본 활동 기록이 적었고 24개 UTC 시간대 모두 기록이 있었다. 감소 원인은 미확인이다. [날짜별 대조](../reports/recency28_support_comparison.csv)를 참고한다.

2026-09-12의 미래 구매 혼입 정정은 3/31 기준에 대한 기록이다. 당시 위험군에서 32,583명의 층이 잘못 분류됐다. [당시 감사 자료와 집계](../reports/archive/n30_ref20200331/README.md), [10/26 민감도 분석 안내](recency_threshold_sensitivity.md)를 보관한다.

## 재현

04 노트북을 실행해 라벨을 만든 후, 새 실행에서 아래 순서로 후보를 검증한다. 원본 경로는 `ECOM_DATA_DIR`로 지정한다.

```bash
python -m src.pre_reference_gap_report
# 별도 사용자 결정 기록에 승인값과 근거 SHA256을 연결한다.
python -m src.recency_reference prepare
python -m src.recency_reference scan
python -m src.ab_design --cache-only
python -m src.recency_validation
```

자동 검증과 독립 검토를 마치면 검증 원본 및 bundle 해시에 별도 검토 기록을 연결한다. 두 해시와 입력을 확인한 실행에서만 `python -m src.ab_design`과 05 노트북이 분석 결과를 생성한다. 기본 A/B 명령은 기존 사전 구매 캐시를 사용한다. 사용자별 입력과 검토 bundle은 로컬 `data/processed/runs/n35_ref20200326/`에 보관한다.

## 한계

- 단일 스토어의 과거 공개 데이터이며, baseline의 현재 서비스 일반화는 검증하지 않았다.
- 수신 동의, 캠페인 비용, 실제 처치 노출·운영 결과를 관찰할 수 없다.
- 실제 운영에서는 데이터 수집 시각·지연도 확인해야 한다. 여기서는 이벤트 시각을 기준으로 제한했다.
- 비정상 활동 후보 제외 시 무제외 대비 군당 표본은 전체 위험군에서 −1~0명, 사전 구매·비구매층까지 포함하면 −1~+1명 변했다([상세](abnormal_user_sensitivity.md)).
