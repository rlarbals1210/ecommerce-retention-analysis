# 이커머스 고객 이탈(Churn) · 리텐션 분석

## 문제 정의
이커머스 서비스에서 신규 고객 획득 비용은 점점 오르는 반면, 기존 고객의 이탈을 조기에
감지하고 방어하는 것은 상대적으로 저렴하고 효과적인 성장 레버다. 이 프로젝트는 다음
질문에 답하기 위해 실제 대규모 행동 로그를 분석한다.

1. 고객은 언제, 얼마나 이탈하는가? (코호트 잔존율)
2. 구매 전환 과정에서 어디서 이탈이 발생하는가? (퍼널 분석)
3. 이탈 위험 세그먼트를 어떻게 정의하고, 리텐션 캠페인의 효과를 어떻게 검증할 것인가? (A/B 테스트 설계)

핵심은 "정확도 높은 예측 모델"이 아니라, **비즈니스 문제를 정의하고 데이터로 검증 가능한
형태로 푸는 과정**을 보여주는 것이다.

## 데이터
- 출처: Kaggle 공개 데이터셋 [eCommerce behavior data from multi category store](https://www.kaggle.com/datasets/mkechinov/ecommerce-behavior-data-from-multi-category-store) — [REES46 Marketing Platform](https://rees46.com/) 제공
- 기간: 2019-10 ~ 2020-04 (월별 CSV 7개, 이벤트 약 2.85억 건 / 총 약 56GB)
- 원본은 로컬 외부 저장 장치에서 **읽기 전용으로 참조**하며 저장소에는 포함하지 않는다. 경로는 환경변수 `ECOM_DATA_DIR`로 주입하고, 미설정 시 `data/raw/`를 사용한다.
- 스키마 (9개 컬럼):

| 컬럼 | 설명 |
|---|---|
| event_time | 이벤트 발생 시각 (UTC) |
| event_type | view / cart / remove_from_cart / purchase |
| product_id | 상품 ID |
| category_id | 카테고리 ID |
| category_code | 카테고리 코드 (결측 32.2%, 01_eda 확인) |
| brand | 브랜드 (결측 14.0%, 01_eda 확인) |
| price | 가격 |
| user_id | 사용자 ID |
| user_session | 세션 ID |

⚠️ 파일당 5–9GB로 매우 크다. 전체를 메모리에 올리지 않고, 필요한 컬럼만 선택 + dtype
최적화 + 필요 시 user_id 기준 샘플링(5–10%)으로 처리한다 (`src/load.py`).

## 방법론
- **코호트 분석**: 데이터에서 사용자가 처음 관측된 활동월(view 포함)을 기준으로 경과 개월별 잔존율을 계산한다. 가입 데이터가 없으므로 실제 신규 가입자와 구분한다. MAU는 해당 월에 활동한 모든 고유 사용자 수다.
- **세션 이벤트 분석**: 동일 세션 내 cart·purchase 이벤트의 존재 여부를 집계한다. `event_time`과 `product_id`를 사용하지 않아 시간순·동일상품 전환을 검증한 퍼널은 아니다. `remove_from_cart`는 보유 데이터에 없어, cart 세션 중 purchase가 없는 비율을 미구매 비율로 정의한다. 월별 고유 세션 수를 합산했으며 월 경계 중복은 별도 검증하지 않았다.
- **이탈(churn) 정의**: 마지막 활동 이후 N일 무활동을 이탈로 정의. 04_churn_features에서
7개월 전체 재방문 간격을 재검증해 **N = 30일로 설정**했다 (90번째 percentile인 35일에
가깝고 운영 시점에서 해석하기 쉬운 기준).
`config.py`의 `CHURN_INACTIVITY_DAYS = 30`.
- **우측 절단(right-censoring) 처리**: 데이터 종료일 근처에 유입된 유저는 "아직 이탈할
시간이 없었을 뿐"이므로 이탈 여부를 확정할 수 없다. 종료일에서 30일을 뺀 시점을 기준으로
그 이전 활동 이력이 있는 유저만 판정하고, 최근 30일 내 신규 유입 유저는 `censored`
(판단 보류)로 분리해 이탈률 집계에서 제외한다.
- **A/B 테스트 설계**: 실제 실험 대신, 이탈 위험 세그먼트를 대상으로 한 리텐션 캠페인의 A/B
테스트 설계 문서(대상 정의, 지표, 표본 크기 산정, 실험 기간, 검정 방법)를 작성.

  - 재방문 집단의 구매 경험자 구성비 31.5% vs 미활동 집단 10.3%는 **4월까지 포함한 사후 기술통계**다. 사전 구매 경험의 예측력·인과효과 근거로 쓰지 않으며, A/B 층화에는 이 피처를 재사용하지 않는다.
  - 생성 피처: `status`(churned / retained / censored), `recency_days`, `active_days`, `active_months`, `purchase_count`, `purchase_days`, `total_spend`, `is_buyer`, `repeat_buyer`, `cohort_month`
- [x] 05_ab_test_design: Recency 15~29일 위험군 대상 리텐션 캠페인 사전 설계안 공개
  - Recency와 구매 이력을 모두 2020-03-31 UTC 하루 종료까지 제한한다. 결과는 4/1–4/30에 관측한다.
  - `is_buyer_at_reference`로 층화하고 각 층 안에서 처치·대조 1:1 배정. 7개월 전체 `is_buyer`는 사후 기술통계 전용이다.
  - 지표: 30일 재방문율(primary) / 구매율·객단가(secondary) / 수신거부율·할인비용·contribution margin(guardrail)
  - alpha 0.05, power 0.80, MDE 절대 +5%p. [재계산 표본·baseline](docs/ab_test_design.md)은 [집계 CSV](reports/ab_design_summary.csv)와 같은 함수에서 생성한다. 전체 표본 확보가 층별 검정력까지 보장하지는 않는다.
  - 실제 캠페인 결과가 아니라 공개 데이터에 기반한 **사전 설계안**

## 한계
- 단일 스토어의 공개 데이터라 일반화에 한계가 있다.
- 실제 실험을 집행할 수 없어 A/B는 **설계 단계까지**만 다룬다.
- 2019-10 ~ 2019-11 구간은 cart 이벤트 로깅이 불안정한 것으로 보여 해당 기간이 포함된 cart 관련 퍼널 지표는 방향성으로만 해석한다.

### 데이터 자체의 한계 — 코호트 좌측 절단 (2026-09-11 추가)

코호트별 1개월 잔존율은 46.4% → 35.8% → 26.1% → 23.1% → 22.5% → 20.4%로 계속 떨어진다.
그대로 읽으면 "신규 유입의 질이 악화됐다"는 결론이 나오지만, **그렇게 읽으면 안 된다.**

**2019-10은 데이터의 첫 달이다.** 그 이전부터 활동하던 기존 유저가 "10월에 처음 활동한 것"으로
잡히므로, 기존 사용자와 신규 관측자를 분리할 수 없다. 기존 사용자가 수치 차이를 얼마나 설명하는지는 추정하지 않았다. 이후 코호트와 직접 비교하지 않는 **좌측 절단(left truncation)** 제약이다.

위 '우측 절단 처리'는 정교하게 반영했으나 좌측은 데이터 자체의 제약이라 보정할 수 없다.
**해석 시 2019-10 코호트를 코호트 간 비교에서 제외한다.**

### 데이터 품질 이슈 — 2019-10~11 cart 이벤트 수집 불완전 (2026-09-11 추가)

같은 세션에 cart 기록 없이 purchase만 존재한 세션 수다. 실제 행동 순서나 바로 구매한 이유를 확인한 것은 아니다.

|---|---|---|---|
| 2019-10 | 9,244,421 | 573,098 | **337,699** |
| 2019-11 | 13,776,050 | 1,743,343 | **124,851** |
| 2019-12 | 15,581,360 | 1,983,488 | 11,983 |
| 2020-01 | 13,847,854 | 1,543,485 | 11,577 |
| 2020-02 | 13,544,595 | 1,660,110 | 53,922 |
| 2020-03 | 12,658,462 | 1,638,659 | 11,921 |
| 2020-04 | 11,652,261 | 1,826,140 | 2,794 |

10월에는 purchase 세션의 53.6%에 cart 기록이 없었다. 11월은 16.2%, 이후는 0.4–7.2%여서 초기 로깅 불안정을 의심했다. 로그 수집 변경 이력은 없어 원인을 확정하지 않았다.

월별 비율 평균이 아니라 분자·분모 합계로 다시 계산하면 전체 기간 cart/전체 세션은 12.15%, cart와 purchase 동시 존재/cart는 44.66%, cart 미구매는 55.34%다. 2019-12 이후는 각각 12.86%, 45.75%, 54.25%다. 미구매 격차는 남지만 원인과 캠페인으로 회수 가능한 비중은 미확인이다.
